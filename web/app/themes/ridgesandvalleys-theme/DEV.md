# Local development — Sage 11 on Bedrock + DDEV

A **Sage 11 (Roots)** theme: Blade + Tailwind v4 + TypeScript + Vite + Acorn, with a
custom-block workflow. The theme repo is standalone; the **main dev environment** is a
**Bedrock + DDEV** WordPress site (the ClaudeCoWork workspace convention) with this repo
bind-mounted in. DDEV runs a pinned **PHP 8.3** + MariaDB in a container, so it's immune
to host-PHP issues and serves a real HTTPS localhost.

## One-time: create the main dev site

Needs the workspace stack (`~/ClaudeCoWork/setup/install-mac-dev.sh` → ddev, composer,
OrbStack). Then:

```bash
cd ~/ClaudeCoWork/setup
./ridgesandvalleys-dev-site.sh
```

This creates `projects/ridgesandvalleys-site` (Bedrock), bind-mounts this theme into
`web/app/themes/ridgesandvalleys-theme`, installs WordPress, activates the theme, and
serves it:

```
  Site:  https://ridgesandvalleys.ddev.site
  Admin: https://ridgesandvalleys.ddev.site/wp/wp-admin   (admin / admin — change it)
```

## Day-to-day (from this theme folder)

```bash
npm start        # build assets + bring the DDEV site up + open it   → https://ridgesandvalleys.ddev.site
npm run dev      # Vite dev server (rebuild-on-save)
npm run build    # production assets → public/build
npm run native   # Docker-free server: local PHP + SQLite + Acorn + Vite HMR → http://localhost:8899
npm run lint:ts  # type-check (tsc --noEmit)
```

- **`npm start`** is the everyday command — it rebuilds assets and boots the DDEV site.
- **`npm run native`** is the quick, Docker-free option with live hot-reload (handy for
  fast Blade/Tailwind/TS iteration). It runs a throwaway WordPress in `.dev-wp/`.
- `bash dev/start.sh --now` runs WordPress Playground (php-wasm) if you want a browser-only preview.

## Vite base (important)

`vite.config.js` sets the theme's public path from `VITE_BASE`, defaulting to Bedrock's
`/app/themes/ridgesandvalleys-theme/public/build/` (the DDEV site). The `--native` server
exports the vanilla `/wp-content/themes/…` path automatically. Build-mode asset URLs are
resolved from the WordPress theme URI at runtime, so this only matters for Vite hot-reload.
**Keep the folder named `ridgesandvalleys-theme`.**

## Where things live

```
functions.php            Boots Acorn + registers app/ files
app/setup.php            Supports, menus, image sizes, fonts, editor assets, theme.json
app/helpers.php          post meta, reading time, icons, social links (used in Blade)
app/projects.php         Projects CPT + taxonomy + details meta box
app/contact.php          Plugin-free contact form + handler
app/customizer.php       Theme Options (colors, layout, CTA, footer, social)
app/blocks.php           Custom block registration + server render (rv/ridgeline-cta)
resources/css/app.css    Tailwind v4 @theme tokens + component styles
resources/js/app.ts      Front-end TypeScript (off-canvas menu)
resources/js/editor.ts   Block editor TypeScript (registers custom blocks)
resources/views/         Blade templates (layouts, sections, partials, pages)
theme.json               Base settings; palette/fonts generated from Tailwind at build
public/build/            Compiled assets (shipped) — regenerated by `npm run build`
vendor/                  Composer deps incl. Acorn (shipped, stripped of tests/vcs)
```

## Custom blocks (no FSE)

Blocks are **dynamic** — server-rendered in `app/blocks.php` via a `render_callback`, with
the editor UI registered from `resources/js/editor.ts` (TypeScript; Tailwind classes work
in the preview). The bundled **Ridgeline CTA** (`rv/ridgeline-cta`) is a full example.

## Verified

PHP errors**. The Bedrock+DDEV site setup mirrors your `setup/new-sage-project.sh`.
